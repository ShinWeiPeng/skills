# 通用技能流程統整與測試目錄治理收斂

## Problem
使用者要求重新討論通用技能治理責任，而非繼續補強 v1 所建議的 layout AST 分析。多份流程規格交疊，且目錄治理包含使用者本轮明確表示不應存在的測試依賴、隔離及分析能力要求。v1 補齊語言分析器的候選方向已撤回，不得當成已採納或已授權的實作。

## Solution
由本SPEC明列跨輪討論、保存、提問恢復、共用修改入口及授權的統整與歷史取代關係，保留識別碼修復。目錄治理移除附帶的依賴、隔離及AST分析要求；適用驗證計畫隨完整SPEC確認並接入原流程。SPEC為驗收定義的唯一人工來源，自動產生工具對照。SPEC-0031～0033僅相容性驗證，不預定修改；其他依已採納處置保留或整合。歷史SPEC不直接改寫；任何SPEC修訂撤銷舊授權。整體方案仍待完成需求/驗收對照與呈現後由使用者一次確認。

## User Stories
使用者希望通用技能能持續產生及維護 SPEC、保留有效授權與問題脈絡，並確實執行適用的模組化驗證，而不是疊加造成循環阻擋的關卡。

| REQ-015 | 需求及驗收標準未變但必要装置或外部驗證環境暫時不可用時，繼續已授權且可獨立完成的修改與驗證；缺少的層級保持待驗證，保留已取得證據，不宣告整體完成或以其他層級替代。條件具備後接續原計畫；如需變更需求或門檻，依 REQ-010 暫停整個變更集。 |
| REQ-016 | 提供決策選項時至少三項，分別說明情境、影響與取捨；不使用重複或虛假的方案冒充不同選項。接受數字或清楚自由文字作答；模糊回答先釐清，不能自動採納。 |
| REQ-017 | 任何 SPEC 修訂均撤銷先前產品執行授權，包括文字修正、證據更新、討論追加造成的修訂及沒有需求語意變更的修訂；後續產品修改需對目前版本重新取得執行授權。未修訂 SPEC 的同範圍修改/修正可沿用仍有效授權。討論及規格保存不因此禁止；本次方案採納不等於執行授權。 |

| REQ-018 | 驗收條件與驗證方法以SPEC為唯一人工維護來源，自動產生工具使用的驗收對照檔；對照檔為可重建的派生資料，不另維護第二套要求。來源變更時更新並核對對照，不把過期對照當目前有效計畫；缺失或歧義如實回報，不推測門檻或偽造結果。執行報告與量測證據另外保存，產生對照不等於驗收通過或新授權。沿用REQ-017，任何SPEC修訂均撤銷舊授權。 |

| REQ-021 | 維持討論需求→確認規格→執行授權→修改程式→執行驗證→判定完成。從工程任務開始建立/接續同一SPEC，每輪保存已知新資訊、決策來源、候選及未決；先讀歷史不重問已答，重複內容不空增版本。候選/否決/延後不冒充採納，純說明可維持working；完整方案呈現後由使用者確認，不能自動代替確認。 |
