# Doc Coauthoring 一鍵安裝

## Problem
Doc Coauthoring currently documents manual copying or plugin marketplace installation. The user requests one-click installation without requiring a plugin.

## Solution
Add direct installation of the existing shared Doc Coauthoring skill without a plugin. Windows uses a double-click launcher; Linux provides a desktop double-click launcher as well as the existing terminal installation command. macOS support and CI execution are outside this change set. The installer lets users choose Codex, Claude Code or both, and defaults to personal scope.
Store versions separately outside skill-discovery directories, for example ~/.doc-coauthoring/versions/<version>/. Each selected tool exposes one active doc-coauthoring skill in its personal skills directory; retain other versions and provide explicit switching/rollback. Activation must not depend on elevated symlink privileges. Verify actual supported host paths and preserve the shared workflow, metadata, relative references and required license/upstream material in the installed payload.
Identical reinstall leaves installed skill files unchanged. Record ownership, version and content identity so modified or unknown files are preserved with an actionable prompt. Stage and validate new content before activation. Failed installation or switching preserves the previous active version, including previously active targets affected by the attempt.
Implement the direct installer and platform launchers, update package installation instructions, add the package-only changeset/release intent and focused installer behavior tests. Use the existing independent Doc Coauthoring release process; do not change the engineering package version or publish a release in this task.

Linux desktop installation uses Install Doc Coauthoring.desktop with Terminal=true and a package-local scripts/install-gui.sh wrapper invoking the existing shell/Python direct installer. Keep interactive Codex/Claude/both selection; display success or failure, actionable diagnostics and the original exit code, then wait for Enter before closing without changing that exit code (EOF must not convert the outcome). Resolve the launch location independently of the current working directory, including local paths or file URIs with spaces and Unicode. Document first-launch execution/trust actions required by the desktop environment. Include both launch files in required release contents and integrity verification, update the existing pending changeset/release intent and Linux desktop/terminal documentation, and add focused behavior, path and artifact coverage. Require actual desktop execution in an isolated Ubuntu graphical user session; shell-only tests cannot replace it. Untested desktop variants and missing capabilities remain explicit.

## User Stories
As a Doc Coauthoring user, I can install the skill without configuring a plugin marketplace or manually copying its files.
